# Навигация робота в Gazebo

Тестовое задание на автономный проезд из точки A в точку B с объездом препятствий.
В проекте используется собственный четырёхколёсный робот (упрощённая модель) с LiDAR, камерой глубины и GPS.
Сцена небольшая: пять препятствий, наружные стены и две цветные зоны.
Зелёная — старт `A = (-4, -3)`, красная — финиш `B = (4, 3)`.

Всё работает в Docker: Ubuntu 22.04, ROS 2 Humble и Gazebo Classic 11.
Навигация — Nav2 с AMCL и сохранённой картой. Свои узлы написаны на Python.

## Запуск

Для Windows нужны Docker Desktop в режиме Linux containers и PowerShell.
Команды выполняются из корня репозитория.

```powershell
.\scripts\run_demo.ps1
```

Скрипт собирает образ и ROS-пакеты, запускает Gazebo и RViz.
Когда сенсоры и навигация готовы, робот сам начинает движение по шести GPS-точкам.
Начальную позицию и цели вручную задавать не нужно.

Окна Gazebo и RViz доступны в браузере: [localhost:6080/vnc.html](http://localhost:6080/vnc.html).
Первый запуск занимает больше времени: Docker скачивает зависимости и собирает образ.
Терминал нужно оставить открытым. `Ctrl+C` останавливает симуляцию.

Если образ уже собран и Dockerfile не менялся:

```powershell
.\scripts\run_demo.ps1 -SkipImageBuild
```

Запуск без окон и полная остановка контейнера:

```powershell
.\scripts\run_demo.ps1 -Headless
.\scripts\stop.ps1
```

На Linux:

```bash
docker compose -f docker/docker-compose.yml up -d --build --force-recreate
docker exec -it gazebo-autonomy-test bash /workspace/scripts/run_demo.sh
```

## Как устроена навигация

AMCL определяет положение робота на карте по LiDAR. NavFn строит путь,
а DWB выбирает скорость и поворот с учётом ближайших препятствий.
Команды проходят через сглаживание скорости и Collision Monitor,
после чего поступают на привод по `/cmd_vel_safe`.

| Датчик | Топик | Для чего используется |
| --- | --- | --- |
| 2D LiDAR | `/scan` | Локализация, карты препятствий и защита от столкновений |
| Камера глубины, аналог Astra | `/camera/depth_camera/points` | Обнаружение препятствий в локальной costmap |
| GPS | `/gps/fix` | Маршрут в GPS-координатах и проверка прибытия |

Камера настроена на 320×240 и 5 Гц, используется `libgazebo_ros_camera.so`.
GPS работает через `libgazebo_ros_gps_sensor.so` — штатный плагин для ROS 2.
В RViz видны карта, робот, путь, препятствия, GPS-точки и изображение глубины.

Цепочка TF:

```text
map -> odom -> base_footprint -> base_link -> датчики
```

`map -> odom` публикует AMCL, одометрию даёт плагин привода Gazebo,
а преобразования между звеньями модели — robot_state_publisher.

Маршрут находится в `src/autonomy_navigation/config/waypoints.yaml`.
Точки заданы широтой и долготой WGS84, направление робота — углом `yaw` в радианах.
Опорные координаты мира: 55° с. ш., 37° в. д., высота 100 м.
Узел миссии переводит точки в координаты карты и по очереди отправляет цели Nav2.
Прибытие проверяется по AMCL и GPS с учётом смещения GPS-антенны на роботе.
Если данные устарели или цель не достигнута за отведённое время, миссия останавливается.
Текущее состояние публикуется в `/mission/status`.

Основные настройки лежат в `src/autonomy_navigation/config/nav2_params.yaml`:
скорость до 0,22 м/с, поворот до 0,45 рад/с, footprint 0,52×0,44 м с запасом 1 см.
Радиус inflation — 0,5 м, допуск достижения цели — 0,18 м и 0,3 рад.
Collision Monitor проверяет возможное столкновение на секунду вперёд.

## Карта

Для обычного запуска используется готовая карта с разрешением 5 см.
Две дополнительные перегородки внесены в неё по координатам мира Gazebo.

Отдельно можно запустить SLAM Toolbox. Для этого нужно остановить навигацию
и в двух терминалах контейнера с загруженным ROS-окружением выполнить:

```bash
ros2 launch autonomy_gazebo simulation.launch.py
```

```bash
ros2 launch autonomy_navigation slam.launch.py
```

AMCL и SLAM одновременно запускать не нужно: оба публикуют `map -> odom`.
При замене карты нужно проверить её систему координат и соответствие GPS-маршруту.

## Проверка проезда

На этом лабиринте прошли три последовательных запуска и отдельный запуск с записью видео.
Проезд занимает примерно полторы минуты. Минимальный измеренный зазор в проверенной серии — 27 см;
контактов с препятствиями в потоке физических контактов Gazebo не зафиксировано.

Проверку можно повторить. Сначала остановить текущую симуляцию через `Ctrl+C`,
оставив контейнер работающим, затем выполнить:

```bash
docker exec gazebo-autonomy-test bash -lc 'source /opt/ros/humble/setup.bash; source /opt/tf2_compat/setup.bash; python3 /workspace/scripts/check_navigation.py --runs 3 --report /tmp/maze_validation.json'
```

Скрипт проверяет прибытие, сообщения сенсоров, зазор и физические контакты.
Контакт колёс с полом разрешён. Результаты сохраняются в `/tmp/maze_validation.json`.
Есть 18 тестов для GPS-проекции, маршрута, карты и проверки столкновений.

## Особенности окружения

В образе закреплён `tf2_ros` 0.25.22: версия 0.25.23 в этом окружении приводила
к зависанию обновления TF. Сборка этой зависимости находится в `docker/build_tf2_compat.sh`.
Окружение `/opt/tf2_compat` подключается автоматически после ROS и пакетов проекта.
Fast DDS использует UDP-профиль `docker/fastdds.xml`, чтобы избежать сбоев
при повторных запусках в контейнере. Эти настройки уже включены в обычный запуск.
